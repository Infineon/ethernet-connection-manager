# Ethernet Connection Manager (ECM) - Wired Ethernet Connectivity for Infineon MCUs

# Overview

Ethernet Connection Manager (ECM) is a ModusToolbox&trade; middleware library that helps application developers establish and manage wired Ethernet connectivity on Infineon platforms that support Ethernet. It provides a thread-safe set of APIs to configure the Ethernet interface, connect to and disconnect from the network, retrieve address information, and monitor link state through an event-notification mechanism. The library uses the Ethernet configuration generated by the ModusToolbox&trade; Device Configurator.

ECM is part of the ModusToolbox&trade; framework for connectivity applications based on FreeRTOS, lwIP, and Mbed TLS, and is built on top of the abstraction-rtos library, which provides the RTOS abstraction API for FreeRTOS. Applications typically consume ECM indirectly through the [ethernet-core-freertos-lwip-mbedtls](https://github.com/Infineon/ethernet-core-freertos-lwip-mbedtls) core library, which pulls in ECM together with secure-sockets, FreeRTOS, lwIP, and Mbed TLS.

## Supported Platforms

This library and its features are supported on the following Infineon device families:

- PSOC&trade; Edge E84
- XMC7200 (with an external Ethernet PHY; for example, KIT_XMC72_EVK)
- XMC7100 (with an external Ethernet PHY; for example, KIT_XMC71_EVK_LITE_V1)
- TRAVEO&trade; T2G CYT3DL (with an external Ethernet PHY; for example, KIT_T2G_C-2D-4M_LITE)
- TRAVEO&trade; T2G CYT4DN (with an external Ethernet PHY; for example, KIT_T2G_C-2D-6M_LITE)
- TRAVEO&trade; T2G CYT6BJ (with an external Ethernet PHY; for example, KIT_T2G_B-H-16M_LITE)

# Features

- Configure and bring up the Ethernet interface, and connect to or disconnect from the network
- Static IP or DHCP-based IP address assignment, with APIs to retrieve IPv4/IPv6, gateway, netmask, and MAC addresses
- Up to four source and destination MAC address filters
- Enable or disable reception of broadcast frames, and enable or disable promiscuous mode
- Connection monitoring with link up/down and IP-change event notifications through a registered callback
- Thread-safe APIs for use in FreeRTOS-based applications

# When to Use

Use ECM when your application needs wired Ethernet connectivity on an Infineon MCU that provides an Ethernet MAC (for example, an XMC7200- or XMC7100-based design driving an external Ethernet PHY). It is the right choice when you need to:

- Bring a wired network interface up and down under application control
- Obtain an IP address over DHCP or configure a static IP
- React to cable connect/disconnect and IP-change events at runtime
- Apply MAC-level address filtering, broadcast control, or promiscuous mode

If your application uses the socket layer, ECM is normally pulled in transitively by ethernet-core-freertos-lwip-mbedtls rather than added directly.

# Prerequisites

## Hardware Requirements

- An Infineon MCU with an Ethernet MAC and a supported external Ethernet PHY. Validated designs use:
  - XMC7200 (KIT_XMC72_EVK) with an RGMII interface and a DP83867IR PHY
  - XMC7100 (KIT_XMC71_EVK_LITE_V1) with an RMII interface and a DP83825I PHY
  - TRAVEO&trade; T2G CYT3DL (KIT_T2G_C-2D-4M_LITE) with an RMII interface and a DP83848VV or LAN8720A PHY
  - TRAVEO&trade; T2G CYT4DN (KIT_T2G_C-2D-6M_LITE) with an RGMII interface and an RTL8211FI PHY
  - TRAVEO&trade; T2G CYT6BJ (KIT_T2G_B-H-16M_LITE) with an RMII interface and a LAN8670 PHY
- An Ethernet cable and access to a network (with a DHCP server, unless a static IP is configured)

**Note:** Ethernet is not a deep-sleep-enabled IP; the system must remain in Active power mode for the interface to operate.

## Add Required Libraries

Add the required libraries using the ModusToolbox&trade; Library Manager (available in the ModusToolbox&trade; for VS Code extension and the Eclipse IDE), or by creating the corresponding `.mtb` files in the application's `deps` folder and running `make getlibs`.

- [ethernet-core-freertos-lwip-mbedtls](https://github.com/Infineon/ethernet-core-freertos-lwip-mbedtls) (latest-v2.X) - Core library that internally pulls secure-sockets, ethernet-connection-manager, FreeRTOS, lwIP, Mbed TLS, and other dependent modules
- [ethernet-phy-driver](https://github.com/Infineon/ethernet-phy-driver) (latest-v1.X) - Ethernet PHY driver whose callbacks are passed to `cy_ecm_ethif_init()`

To add these by hand, create the following `.mtb` files in the `deps` folder and run `make getlibs`:

- ethernet-core-freertos-lwip-mbedtls.mtb:
  `https://github.com/Infineon/ethernet-core-freertos-lwip-mbedtls#latest-v2.X#$$ASSET_REPO$$/ethernet-core-freertos-lwip-mbedtls/latest-v2.X`
- ethernet-phy-driver.mtb:
  `https://github.com/Infineon/ethernet-phy-driver#latest-v1.X#$$ASSET_REPO$$/ethernet-phy-driver/latest-v1.X`

**Note:** ethernet-connection-manager is pulled in as a dependency of ethernet-core-freertos-lwip-mbedtls, so most applications do not add it directly.

## Configure Makefile (if applicable)

Add the following flags to the `DEFINES` variable in the application Makefile as needed:

```
DEFINES+=CYBSP_ETHERNET_CAPABLE
```

- `CYBSP_ETHERNET_CAPABLE` - Enables the Ethernet functionality (required).
- `CY_DISABLE_XMC7000_DATA_CACHE` - Disables the data cache on XMC7000 devices.
- `ENABLE_ECM_LOGS` - Enables ECM debug log messages (disabled by default). When enabled, call `cy_log_init()` from the cy-log module (part of the connectivity-utilities library) to route the logs. See the [Connectivity Utilities Reference Manual](https://Infineon.github.io/connectivity-utilities/api_reference_manual/html/group__logging__utils.html) for cy-log details.

Example enabling all three flags:

```
DEFINES+=CYBSP_ETHERNET_CAPABLE
DEFINES+=CY_DISABLE_XMC7000_DATA_CACHE
DEFINES+=ENABLE_ECM_LOGS
```

## Configure in the Tool (if applicable)

ECM uses the Ethernet configuration generated by the ModusToolbox&trade; Device Configurator. Open the `design.modus` file and apply the settings below.

Common (all platforms) - keep the system in Active power mode:

- Switch to the "System" tab.
- Select Resource -> Power.
- In the "RTOS" section, set "System Idle Power Mode" to "Active".
- Save the configuration to generate the necessary code.

XMC7200 (KIT_XMC72_EVK) - configure the PHY:

- Switch to the "Peripherals" tab.
- Select Communication -> "Ethernet 1".
- In the "Ethernet - Parameters" pane, set the interface type "PHY Interconnect" to "RGMII".
- Set the PHY driver "PHY device" to "DP83867IR".
- Enable or disable "Autonegotiation" (default: enabled).
- Configure "PHY speed" (10/100/1000 Mbits/sec) and "PHY Duplex mode" (default: Full Duplex).
- Configure "Mac Address".
- Enable "Promiscuous mode" (default: disabled).
- Enable "Accept Broadcast Frames" (default: enabled).
- Configure "Mac Reference Clock" (default: External clk).
- Configure "Nvic Mux Interrupt number" (enabled when the device has separate NVIC interrupt lines; default: 3).
- Configure a static IP or use DHCP (default: DHCP).
- Save the configuration to generate the necessary code.

XMC7100 (KIT_XMC71_EVK_LITE_V1) - configure the PHY:

- Switch to the "Peripherals" tab.
- Select Communication -> "Ethernet 0".
- In the "Ethernet - Parameters" pane, set the interface type "PHY Interconnect" to "RMII".
- Set the PHY driver "PHY device" to "DP83825I".
- Enable or disable "Autonegotiation" (default: enabled).
- Configure "PHY speed" (10/100 Mbits/sec) and "PHY Duplex mode" (default: Full Duplex).
- Configure "Mac Address".
- Enable "Promiscuous mode" (default: disabled).
- Enable "Accept Broadcast Frames" (default: enabled).
- Configure "Mac Reference Clock" (default: External clk).
- Configure "Nvic Mux Interrupt number" (enabled when the device has separate NVIC interrupt lines; default: 3).
- Configure a static IP or use DHCP (default: DHCP).
- Save the configuration to generate the necessary code.

TRAVEO&trade; T2G CYT3DL (KIT_T2G_C-2D-4M_LITE) - configure the PHY and MAC reference clock:

- Switch to the "Peripherals" tab.
- Select Communication -> "Ethernet 0".
- In the "Ethernet - Parameters" pane, set the interface type "PHY Interconnect" to "RMII".
- Set the PHY driver "PHY device" to "DP83848VV" or "LAN8720A".
- Enable or disable "Autonegotiation" (default: enabled).
- Configure "PHY speed" (10/100 Mbits/sec) and "PHY Duplex mode" (default: Full Duplex).
- Configure "Mac Address".
- Enable or disable "Promiscuous mode" (default: disabled).
- Enable or disable "Accept Broadcast Frames" (default: enabled).
- Configure "Mac Reference Clock" (default: External clk) to match the kit's clock source and ensure a 50-MHz reference clock at all link speeds.
- Configure "Nvic Mux Interrupt number" (enabled when the device has separate NVIC interrupt lines; default: 3).
- Configure a static IP or use DHCP (default: DHCP).
- Save the configuration to generate the necessary code.

Connect either a DP83848VV or a LAN8720A PHY module externally to Ethernet 0 (eth0) on the kit. Both modules use RMII and provide a stable 50-MHz reference clock at both 10 and 100 Mbits/sec.

TRAVEO&trade; T2G CYT4DN (KIT_T2G_C-2D-6M_LITE) - configure the PHY and MAC reference clock:

- Switch to the "Peripherals" tab.
- Select Communication -> "Ethernet 0".
- In the "Ethernet - Parameters" pane, set the interface type "PHY Interconnect" to "RGMII".
- Set the PHY driver "PHY device" to "RTL8211FI".
- Enable or disable "Autonegotiation" (default: enabled).
- Configure "PHY speed" (10/100/1000 Mbits/sec) and "PHY Duplex mode" (default: Full Duplex).
- Configure "Mac Address".
- Enable or disable "Promiscuous mode" (default: disabled).
- Enable or disable "Accept Broadcast Frames" (default: enabled).
- Configure "Mac Reference Clock" (default: External clk) to match the kit's clock source and ensure a 125-MHz reference clock at all link speeds.
- Configure "Nvic Mux Interrupt number" (enabled when the device has separate NVIC interrupt lines; default: 3).
- Configure a static IP or use DHCP (default: DHCP).
- Save the configuration to generate the necessary code.

ECM selects the CYT4DN transmit-clock dividers automatically: 50 at 10 Mbits/sec, 5 at 100 Mbits/sec, and 1 at 1000 Mbits/sec, producing 2.5, 25, and 125 MHz, respectively, from the 125-MHz reference clock.

TRAVEO&trade; T2G CYT6BJ (KIT_T2G_B-H-16M_LITE) - configure the PHY and MAC reference clock:

- Switch to the "Peripherals" tab.
- Select Communication -> "Ethernet 0".
- In the "Ethernet - Parameters" pane, set the interface type "PHY Interconnect" to "RMII".
- Set the PHY driver "PHY device" to "LAN8670".
- Configure "PHY Address" to "1" for KIT_T2G_B-H-16M_LITE.
- Disable "Autonegotiation" (default: disabled for LAN8670).
- Configure "PHY speed" to 10 Mbits/sec. "PHY Duplex mode" is fixed to Half Duplex for LAN8670.
- Configure "Mac Address".
- Enable or disable "Promiscuous mode" (default: disabled).
- Enable or disable "Accept Broadcast Frames" (default: enabled).
- Configure "Mac Reference Clock" (default: External clk) to match the kit's clock source and ensure a 50-MHz reference clock for RMII.
- Configure "Nvic Mux Interrupt number" (enabled when the device has separate NVIC interrupt lines; default: 3).
- Configure a static IP or use DHCP (default: DHCP).
- Configure "Multidrop Enable (LAN8670)" and the mode in the "PLCA (LAN8670)" section to match the network topology.
- Save the configuration to generate the necessary code.

LAN8670 uses 10BASE-T1S at 10 Mbits/sec in Half Duplex. PLCA requires one coordinator (ID 0), unique follower IDs, a coordinator "Node Count:" greater than the highest node ID, and the same transmit opportunity timer value on all nodes.

**Note:** "PHY speed" and "PHY Duplex Mode" are visible only when "Autonegotiation" is disabled.

**Note:** At 100 Mbits/sec, intermittent connection issues have been observed on certain (enterprise) networks, as well as issues when receiving data larger than a 4 KB buffer. The recommended configuration is 1000 Mbits/sec or Autonegotiation.

For PHY pin connections, refer to the "Quick Start" section of the [Ethernet PHY Driver README](https://github.com/Infineon/ethernet-phy-driver).

# Quick Start

This quick start demonstrates bringing up the Ethernet interface, obtaining an IP address, and monitoring the link. It assumes an Empty application with the libraries added and the Device Configurator settings applied as described in the Prerequisites section.

**Step 1:** Add the ethernet-core-freertos-lwip-mbedtls and ethernet-phy-driver libraries (see the Add Required Libraries section).

**Step 2:** Apply the Device Configurator settings for your kit (see the Configure in the Tool section) and add `DEFINES+=CYBSP_ETHERNET_CAPABLE` to the Makefile.

**Step 3:** Provide the PHY operation callbacks from the ethernet-phy-driver library to ECM through `cy_ecm_ethif_init()`.

**Step 4:** Add the code below to your `main.c` (see the Sample Code section for complete examples) to initialize ECM, connect, and retrieve the IP address.

**Expected Outcome:** The interface links up, a valid IPv4 address is obtained over DHCP, and ECM reports connection and IP-change events. See the Expected Outcome section.

## Sample Code

The following examples are complete and mirror the snippets published in the Reference Manual. The PHY callbacks come from the ethernet-phy-driver library.

### Initialize the Ethernet Interface

This example initializes the Ethernet driver and network stack and creates an ECM handle using `cy_ecm_ethif_init()`.

```c
#include "cy_ecm.h"
#include "cy_eth_phy_driver.h"

cy_ecm_t ecm_handle;

cy_ecm_phy_callbacks_t eth_phy_callbacks =
{
    .phy_init = cy_eth_phy_init,
    .phy_configure = cy_eth_phy_configure,
    .phy_enable_ext_reg = cy_eth_phy_enable_ext_reg,
    .phy_discover = cy_eth_phy_discover,
    .phy_get_auto_neg_status = cy_eth_phy_get_auto_neg_status,
    .phy_get_link_partner_cap = cy_eth_phy_get_link_partner_cap,
    .phy_get_linkspeed = cy_eth_phy_get_linkspeed,
    .phy_get_linkstatus = cy_eth_phy_get_linkstatus,
    .phy_reset = cy_eth_phy_reset
};

void ecm_ethernet_init(void)
{
    cy_rslt_t result = CY_RSLT_SUCCESS;

    /* Initialize the ECM library and network stack */
    result = cy_ecm_init();
    if (result != CY_RSLT_SUCCESS)
    {
        /* Failure path */
    }

    /* Initialize the Ethernet driver with the provided PHY callbacks */
    result = cy_ecm_ethif_init(CY_ECM_INTERFACE_ETH1, &eth_phy_callbacks, &ecm_handle);
    if (result != CY_RSLT_SUCCESS)
    {
        /* Failure path */
    }
}
```

### Configure Ethernet Features

This example enables promiscuous mode, controls broadcast reception, and adds a source-address filter using `cy_ecm_set_promiscuous_mode()`, `cy_ecm_broadcast_disable()`, and `cy_ecm_set_filter_address()`.

```c
void ecm_ethernet_features_enable(void)
{
    cy_rslt_t result = CY_RSLT_SUCCESS;
    bool is_promiscuous_mode = true;
    uint8_t filter_address_count;
    cy_ecm_filter_address_t filter_address;

    result = cy_ecm_init();
    if (result != CY_RSLT_SUCCESS)
    {
        /* Failure path */
    }

    result = cy_ecm_ethif_init(CY_ECM_INTERFACE_ETH1, &eth_phy_callbacks, &ecm_handle);
    if (result != CY_RSLT_SUCCESS)
    {
        /* Failure path */
    }

    /* Enable promiscuous mode */
    result = cy_ecm_set_promiscuous_mode(ecm_handle, is_promiscuous_mode);
    if (result != CY_RSLT_SUCCESS)
    {
        /* Failure path */
    }

    /* Allow broadcast frames to be received */
    result = cy_ecm_broadcast_disable(ecm_handle, false);
    if (result != CY_RSLT_SUCCESS)
    {
        /* Failure path */
    }

    /* Add a source-address filter */
    filter_address_count = 1;
    filter_address.filter_type = CY_ECM_FILTER_TYPE_SOURCE;
    memset(&(filter_address.filter_addr[0]), 0xFF, CY_ECM_MAC_ADDR_LEN);
    filter_address.ignoreBytes = 0x00;

    result = cy_ecm_set_filter_address(ecm_handle, &filter_address, filter_address_count);
    if (result != CY_RSLT_SUCCESS)
    {
        /* Failure path */
    }
}
```

### Connect and Retrieve IP Address

This example connects to the Ethernet interface, brings up the network, and reads the IP, gateway, and netmask addresses using `cy_ecm_connect()`, `cy_ecm_get_ip_address()`, `cy_ecm_get_gateway_address()`, and `cy_ecm_get_netmask_address()`.

```c
static cy_ecm_ip_address_t ip_addr;
static cy_ecm_ip_address_t gateway_addr;
static cy_ecm_ip_address_t net_mask_addr;

void ecm_connect_and_get_ip(void)
{
    cy_rslt_t result = CY_RSLT_SUCCESS;

    result = cy_ecm_init();
    if (result != CY_RSLT_SUCCESS)
    {
        /* Failure path */
    }

    result = cy_ecm_ethif_init(CY_ECM_INTERFACE_ETH1, &eth_phy_callbacks, &ecm_handle);
    if (result != CY_RSLT_SUCCESS)
    {
        /* Failure path */
    }

    /* Connect and bring up the network. Pass a static IP setting instead of
       NULL to use a static address; NULL requests a DHCP-assigned address. */
    result = cy_ecm_connect(ecm_handle, NULL, &ip_addr);
    if (result != CY_RSLT_SUCCESS)
    {
        /* Failure path */
    }

    result = cy_ecm_get_ip_address(ecm_handle, &ip_addr);
    if (result != CY_RSLT_SUCCESS)
    {
        /* Failure path */
    }

    result = cy_ecm_get_gateway_address(ecm_handle, &gateway_addr);
    if (result != CY_RSLT_SUCCESS)
    {
        /* Failure path */
    }

    result = cy_ecm_get_netmask_address(ecm_handle, &net_mask_addr);
    if (result != CY_RSLT_SUCCESS)
    {
        /* Failure path */
    }
}
```

    {
        /* Failure path */

### Reconnect / Recovery Example

Register an event callback to monitor link state, and re-establish the connection when the cable is disconnected. `CY_ECM_EVENT_IP_CHANGED` is also reported after a reconnect or a DHCP renewal.

```c
static void ecm_event_callback(cy_ecm_event_t event, cy_ecm_event_data_t *event_data)
{
    (void)event_data;

    switch (event)
    {
        case CY_ECM_EVENT_CONNECTED:
            /* Ethernet link is up */
            break;
        case CY_ECM_EVENT_DISCONNECTED:
            /* Ethernet link is down; signal the application to reconnect */
            break;
        case CY_ECM_EVENT_IP_CHANGED:
            /* A new IP address was assigned (connect, reconnect, or DHCP renewal) */
            break;
    }
}

void ecm_reconnect_loop(void)
{
    cy_rslt_t result = CY_RSLT_SUCCESS;
    bool link_up = false;

    result = cy_ecm_init();
    if (result != CY_RSLT_SUCCESS)
    {
        /* Failure path */
    }

    result = cy_ecm_ethif_init(CY_ECM_INTERFACE_ETH1, &eth_phy_callbacks, &ecm_handle);
    if (result != CY_RSLT_SUCCESS)
    {
        /* Failure path */
    }

    /* Register for connection state and IP-change notifications */
    result = cy_ecm_register_event_callback(ecm_handle, ecm_event_callback);
    if (result != CY_RSLT_SUCCESS)
    {
        /* Failure path */
    }

    /* Initial connection */
    result = cy_ecm_connect(ecm_handle, NULL, &ip_addr);

    /* Recovery loop: re-establish the connection if the link goes down */
    for (;;)
    {
        result = cy_ecm_get_link_status(ecm_handle, &link_up);
        if ((result == CY_RSLT_SUCCESS) && (link_up == false))
        {
            cy_ecm_disconnect(ecm_handle);
            result = cy_ecm_connect(ecm_handle, NULL, &ip_addr);
        }
        cy_rtos_delay_milliseconds(1000);
    }
}
```

## Expected Outcome

When the Quick Start example runs successfully, you should observe:

Visual/Hardware Behavior:

- The Ethernet link LED on the RJ45 connector turns on when a cable is connected and a link is established.
- On cable removal, ECM reports a disconnect; on reinsertion, it reconnects and reports a new IP address.

Terminal Output (with `ENABLE_ECM_LOGS` enabled; addresses depend on your network):

```
ECM initialized
Ethernet PHY initialized
Ethernet link up
IP Address 192.168.1.100 assigned
Ping successful, elapsed time: 2 ms
```

Performance Metrics:

- The recommended link speed is 1000 Mbits/sec (or Autonegotiation) for reliable throughput; see the note in the Configure in the Tool section.

# Troubleshooting

- **ECM API calls hang:** Disable tickless idle mode by defining `configUSE_TICKLESS_IDLE` to `0` in `FreeRTOSConfig.h`. Ethernet is not deep-sleep capable, so the system must stay in Active power mode.
- **Intermittent connectivity or failures with large (>4 KB) transfers at 100 Mbits/sec:** Set the PHY speed to 1000 Mbits/sec or use Autonegotiation.
- **IAR 9.40 build errors when the application includes `iar_dlmalloc.h` in Debug mode:** Add `--advance-heap` to `LDFLAGS` in the application Makefile.
- **No IP address obtained:** Verify the cable and network, confirm a DHCP server is available (or configure a static IP), and confirm "System Idle Power Mode" is set to "Active".
- **No debug output:** Add `DEFINES+=ENABLE_ECM_LOGS` and call `cy_log_init()` from the cy-log module.

# Configuration Reference

ECM is configured through two mechanisms:

- **ModusToolbox&trade; Device Configurator** - Interface type (RGMII/RMII), PHY device, autonegotiation, PHY speed and duplex, MAC address, promiscuous mode, broadcast acceptance, MAC reference clock, NVIC interrupt number, and static IP/DHCP. See the Configure in the Tool section.
- **Makefile `DEFINES`** - Build-time flags:

| Define | Purpose |
| :--- | :--- |
| `CYBSP_ETHERNET_CAPABLE` | Enables Ethernet functionality (required) |
| `CY_DISABLE_XMC7000_DATA_CACHE` | Disables the data cache on XMC7000 devices |
| `ENABLE_ECM_LOGS` | Enables ECM debug log messages |

Runtime configuration APIs include `cy_ecm_set_promiscuous_mode()`, `cy_ecm_broadcast_disable()`, and `cy_ecm_set_filter_address()`. For the complete API reference, see the [Ethernet Connection Manager Reference Manual](https://Infineon.github.io/ethernet-connection-manager/api_reference_manual/html/index.html).
